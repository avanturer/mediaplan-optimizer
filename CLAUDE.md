# MediaPlan Optimizer — кейс МТС (хакатон)

## Принцип работы над проектом (решение Rodion, 2026-09-01)

**Мы не первые. Почти всё уже сделано — наша работа состоит в том, чтобы
грамотно собрать известные решения под конкретный кейс, а не изобретать.**

Из этого следуют жёсткие правила:

1. **Ни одного числа из головы.** Каждая константа в коде и каждая цифра в
   презентации имеет происхождение: либо публичный бенчмарк со ссылкой, либо
   результат нашей калибровки/теста, зафиксированный в репозитории.
   Практика: `config/benchmarks.yaml`, где у каждого значения поля
   `value / source_url / note`. Если источника нет — значение помечено
   `calibrated: true` и рядом лежит тест или ноутбук, который его получил.

2. **Ни одного метода из головы.** Алгоритм выбирается из опубликованных и
   работающих в проде (Yahoo, LinkedIn, Twitter/X, Uber, Alibaba, Amazon) или
   из рецензируемых статей. В коде — комментарий со ссылкой на первоисточник.
   Своё изобретение допустимо только там, где литературы нет, и это явно
   отмечается как наше допущение.

3. **Упрощения фиксируются письменно.** Всё, что мы огрубили (независимые
   ёмкости каналов, отсутствие второй цены и т.д.), перечислено в README
   отдельным разделом. Кейс это прямо разрешает — но только если зафиксировано.

4. **Никакого проприетарного/утёкшего кода в репозитории.** Кейс требует
   создания с нуля; заимствование не проходит правило №2 (его нельзя обосновать
   публичной ссылкой) и создаёт юридический риск. Публичная документация API
   (Яндекс Директ, Google Ads, VK Ads) — можно и нужно: это открытый источник
   для модели данных и UX.

5. **Симулятор и планировщик изолированы.** Планировщик не видит истинных
   параметров мира — только публичный каталог бенчмарков и часовые агрегаты.
   Проверяется тестом: смена seed мира не меняет план.

## Где что лежит
- `contracts/` — схемы границ (каталог, наблюдение, действие, бриф, план, решение). Ни от кого не зависят.
- `world/` — модель мира и симулятор (MLE #1): `reset / step / inject_shock`, три профиля каналов, сценарии шоков.
- `brain/` — планировщик и исполнитель (MLE #2). Никогда не импортирует `world` (import-linter + тест).
- `harness/` — стенд: ретро-пробы, цикл прогона, метрики, парное сравнение стратегий.
- `app/` — FastAPI и веб-кабинет (`app/static/index.html`).
- `config/benchmarks.yaml` — числа с источниками; `config/assumptions.yaml` — допущения мира;
  `config/controller.yaml` — константы мозга с происхождением (проверяет `tests/test_provenance.py`).
- `docs/research.md` — откуда взят каждый метод; `docs/decisions.md` — журнал решений;
  `docs/report.md` — отчёт о правилах распределения и перераспределения; `docs/world/` — контракт мира.
- `scripts/run_demos.py` — три демонстрации и стенд на 20 мирах, результаты в `results/`.

## Как запускать
- `uv venv .venv && uv pip install --python .venv/bin/python -e ".[dev]"` или `docker compose up`
- кабинет: `uvicorn app.main:app --port 8000`, тесты: `python -m pytest -q`, стенд: `python scripts/run_demos.py`
- линт: `ruff check .`, граница пакетов: `lint-imports`
