# Расширения модели мира по обсуждению с Никитой

Дата: 2026-09-05. Никита — эксперт по кейсу; его оценки здесь считаются
требованиями к экспериментам и гипотезами, пока не указана внешняя проверка.
API симулятора: 1.1. Работа реализована в `feature/world-sim`.

## 1. Таргетинг в брифе

`Brief.targeting` и `PublicCatalog.targeting` используют `AudienceTargeting`:

```json
{"age_groups": ["25_34", "35_44"], "genders": ["female"], "geo": ["capital"]}
```

Доступны возрастные группы `18_24`, `25_34`, `35_44`, `45_54`, `55_plus`;
пол `female`, `male`; гео `capital`, `large_cities`, `other_regions`.
Это агрегированные синтетические регионы, не справочник реальных городов.
Пустой список означает все значения. Внутри измерения действует OR, между
измерениями AND. Неизвестные значения и поля отклоняются.

Доли сегментов, региональные цены, эластичность сужения 0,15 и верхняя граница
ценового множителя 2,5 заданы в `config/world_extensions.yaml` как **допущения**.
Измерения независимы; профили одинаковы для каналов. Доля подходящих людей
уменьшает дневную ёмкость и размер пула/SMS-базы. CPM и цена SMS меняются по
региональному множителю и степени сужения. Это сценарная модель цены, а не
утверждение, что всякое сужение в Директе обязательно повышает CPM.

`catalog_for_targeting(base_catalog, targeting)` возвращает публичный каталог
с собственным hash. По нему собираются ретро-пробы на прошлых seeds, затем
строятся кривые. Планировщик отклоняет несовпадение брифа и каталога; runner
проверяет идентификатор каталога плана. `/api/plan` делает весь этот путь,
кэшируя до 32 контекстов сегментов. В UI доступны три селектора; через API
можно выбирать несколько значений.

## 2. Общая аудитория и матрица

Семантика коэффициента: `O[i,j] = |A_i ∩ A_j| / min(|A_i|, |A_j|)`.
Это симметричный overlap coefficient, **не** Jaccard и **не** условная доля
строки GWI. Диагональ равна 1; допустимые элементы конечны и лежат в [0,1].
По умолчанию все внедиагональные элементы равны 0,10 — сценарная гипотеза
по оценке Никиты. `WorldSettings(default_overlap=0)` возвращает независимые
пулы. `overlap_matrix` принимает полную матрицу по каналам каталога.

Реализация: до 28 отдельных общих пулов пар и 8 непересекающихся остатков.
Общий пул пары имеет размер `O[i,j] * min(N_i,N_j)`; он входит в ёмкость
обоих каналов. Для каждого канала сумма общих пулов не должна превышать его
аудиторию. **Тройные пересечения не моделируются**: матрица, для которой
невозможны неотрицательные остатки, отклоняется, а не нормализуется молча.
Например, 15 % у всех семи соседей самого маленького канала уже несовместимы
с этой попарной моделью. Для такого эксперимента нужны неодинаковые пары
или отдельное расширение на пересечения трёх и более каналов.

За час для когорты размера N с каналами C:
`ΔR = (N − R) * (1 − exp(−sum(human_impressions[c] / N_c)))`.
Пулы обновляются одновременно, результат не зависит от порядка каналов.
Учитываются и другие каналы, и все прошедшие часы. Работа пакетная, O(8²).

`by_channel[c].unique_reach` сохраняет смысл новых уникальных **канала**.
`observation.deduplicated_reach` — новые уникальные **кампании**;
`total_reach` читает его, а для старых наблюдений без этого поля суммирует
каналы. `metrics.cumulative_reach` накапливает общий охват.
Округление накопленной аналитической оценки даёт целый прирост; сумма
отдельно округлённых канальных приращений может отличаться на единицы.
Канальная fatigue пока локальная: пересечения меняют дедупликацию,
но не моделируют перенос усталости между площадками.

Исполнитель и runner используют дедуплицированный факт. **Планировщик пока
строит аддитивный прогноз охвата**, о чём сообщает в объяснении плана.
Оптимизация дедуплицированного reach потребует отдельной публичной модели
пересечений или ретро-проб медиасплитов; скрытую матрицу мозгу передавать нельзя.

## 3. Фрод

В `programmatic` доля бот-показов в закупленном инвентаре по умолчанию 0,03.
Шок `fraud` умножает её (с ограничением до 1). В `fraud_surge` множитель 10
с часа 240 на 48 часов, затем линейное восстановление ещё 48 часов.
Боты занимают часть конечных рекламных слотов, поэтому при том же бюджете
вытесняют человеческие показы. Отдельного бесконечного бот-инвентаря нет.

Бот-CTR 0,20; бот-клики не дают конверсий и человеческого охвата. Расход
учитывает и бот-показы: возвраты/фильтрация до закупки здесь не моделируются.
Человеческая воронка разыгрывается отдельно. На парных сериях CTR растёт,
конверсии падают; направление не обещается для каждого случайного часа.

`fraud_share` — **измеренная** доля подозрительных показов. Детектор имеет
sensitivity 0,95 и false positive rate 0,001; оба параметра настраиваются.
`verified_impressions` — показы, не отмеченные детектором; это не истинный
размер человеческой аудитории. При нулевых показах доля равна 0 по соглашению,
UI показывает прочерк. Порог 5 % — сигнал внимания кейса, не доказательство
умышленной атаки. Все эти числа — экспертные/модельные допущения, не нормы MRC.
Будущая доля ботов, их истинное число и параметры детектора в observation не идут.

## 4. Недельный лимит SMS

`sms_weekly_limit` — множитель обычной недельной квоты
`base_size * 7 / cooldown_days`. Разрешено `(0,1]`, например 0,5.
Считаются отправленные, а не доставленные сообщения. Уже сделанные отправки
текущей недели учитываются и при введении лимита посреди недели.

Недели фиксированы относительно старта эпизода: [0,168), [168,336), …;
это **не скользящее окно и не юридический календарь**. Квота обновляется на
границе недели. Окно отправки и исходный cooldown продолжают действовать.
После исчерпания квоты дальнейшие отправки ожидают обновления; после отмены
шока канал работает в обычных пределах. Сценарий ограничивает вторую неделю
вдвое, третья восстанавливается. Это сценарное ограничение из кейса, не
утверждение о действующем законодательстве.

## 5. Сторонние компании

По умолчанию `competitors=[]`. Пример привилегированной конфигурации стенда:

```python
from world.settings import Competitor, WorldSettings

settings = WorldSettings(competitors=[Competitor(
    competitor_id="rival_1", strength=0.8,
    channel_advantages={"programmatic": 2.0, "marketplace_1": 1.0},
    volatility=0.25, start_hour=240, end_hour=400,
)])
```

Сила [0,2], преимущества [0,3], изменчивость [0,1]; отсутствующий канал
означает нулевую активность компании в нём. До 20 компаний с уникальными ID.
Активность — отдельная AR(1)-лента (rho=0,9, sigma=0,25), ограниченная через
tanh до `1 ± volatility`. Давление суммы компаний ограничено 2:
CPM умножается на `1+pressure`, доступность и CVR делятся на него.
В SMS меняется доступность и отклик, фиксированная цена не становится аукционной.
Все диапазоны и коэффициенты — управляемые сценарные допущения.

Это экзогенные сценарные компании: с разумными границами и плавной случайной
активностью, но без обучения, собственного бюджета, реакций на нашу стратегию
и отдельных закупок. Такая версия реализует опциональное рыночное давление;
стратегическое соперничество компаний остаётся отдельной большой задачей.
Ни GPU, ни инфраструктура RL не нужны.

В UI можно включить одну компанию и выбрать её канал/силу. Через
`RunRequest.world_settings` и `RunConfig.world_settings` доступны несколько
компаний и все преимущества. При сравнении с заморозкой настройки одинаковы.
Стратегии получают только последствия: цену, доступность и отклик.

## Повтор эксперимента и проверки

`Simulator(..., settings=settings).reset(seeds, scenario, targeting=...)`
сохраняет каталог, все seeds, настройки, сценарий и параметры запуска.
`export_manifest()` — **привилегированный** рецепт повтора с начала;
`Simulator.from_manifest(manifest)` создаёт чистый эпизод. Затем нужно подать
те же actions. Он не является snapshot для продолжения с середины.
В manifest сохраняются injected shocks, проверяется fingerprint кода мира
и YAML-конфигураций. Для воспроизведения между окружениями нужны совместимые
версии Python/NumPy. Public `info` получает только hash, а не рецепт.

Фрод, измеритель и компании имеют отдельные ключи случайности; смена actions
не расходует общую последовательность RNG. Матрица, сценарий, таргетинг и
настройки входят в config hash. Тесты:

- `tests/test_world_extensions.py`: формулы, невалидные входы, шоки и recovery,
  парность, нулевые/большие caps, 504 часа, сериализация, no-leakage;
- `tests/test_world_api.py`: сегментированный бриф → план → запуск с конкурентом;
- `python -m scripts.validate_world_extensions --seeds 30`: static/adaptive,
  среднее, стандартное отклонение, WAPE и абсолютная ошибка после шока,
  нарушения ограничений. Результат: `results/world_extensions_validation.json`.
